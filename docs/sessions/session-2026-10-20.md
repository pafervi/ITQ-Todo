## 1. Lo que hay que probar

En orden de dependencia, para que si algo falla sepas qué revisar:

1. **La app arranca y los proyectos checklist siguen igual.** La migración `v2_8_0` etiqueta todos los proyectos existentes con `type: "checklist"`. Si falla la migración, se queda en el estado anterior y los proyectos nuevos ya nacen con `type`.
2. **Nuevo proyecto: el diálogo tiene dos pills arriba, Checklist y Phased.** Checklist mantiene el flujo clásico (plantillas). Phased muestra un formulario con nombre, fechas y color.
3. **Un proyecto phased abre con tres tabs en la cabecera: Tasks, Timeline, Feed.** Tasks es el listado clásico de siempre. Timeline y Feed son las dos vistas nuevas.
4. **Añadir fase** desde el menú de 3 puntos del proyecto, o desde el botón del Timeline. Al cerrarla a `done` crea automáticamente un hito en el feed.
5. **Añadir log entry** desde el menú de 3 puntos o desde el botón del Feed. Cuatro tipos: Nota, Hito, Decisión, Bloqueo.
6. **El Timeline pinta los hitos como círculos, las decisiones como rombos y los bloqueos como franjas rayadas** sobre la barra de la fase correspondiente.
7. **Snapshot semanal**: los lunes al abrir sale un modal preguntando por cada proyecto phased ("¿Dónde está esto?"), los viernes otro ("¿Qué cerró?"). Las respuestas no vacías se guardan como notas con marca `monday`/`friday`.

Si el modal no aparece un lunes aunque toque, pulsa F12 en la app y revisa que `config.phasedSnapshotsEnabled === true` y que `config.lastMondaySnapshot` no sea el día de hoy.

## 3. Modelo de datos

### IndexedDB
Dos tablas nuevas, versión bump 4 → 5. `onupgradeneeded` las crea sin romper las existentes.

- `project_phases`: key = `projectId`, value = `Phase[]`
- `project_log_entries`: key = `projectId`, value = `LogEntry[]`

### Shape de las entidades

```js
// Phase
{ id, projectId, name, startDate, endDate, status, order, color }
// status: 'pending' | 'active' | 'done' | 'blocked'

// LogEntry
{ id, projectId, phaseId, date, kind, text, blockEndDate, snapshotKind }
// kind: 'note' | 'milestone' | 'decision' | 'block'
// snapshotKind (opcional): 'monday' | 'friday' si vino del snapshot semanal
```

### cTodoListIds (proyecto) campos nuevos
- `type: 'checklist' | 'phased'` (default `'checklist'`)
- `startDate: 'YYYY-MM-DD' | null` (solo phased)
- `endDate: 'YYYY-MM-DD' | null` (solo phased)

### config.js campos nuevos
- `phasedProjectsIntroduced: true` (flag de la migración, no modificar a mano)
- `lastMondaySnapshot: 'YYYY-MM-DD'`
- `lastFridaySnapshot: 'YYYY-MM-DD'`
- `phasedSnapshotsEnabled: true` (apagar aquí si quieres silenciar los prompts)

## 4. Decisiones aplicadas

Las tres pendientes del plan quedaron:
- **Tipo al crear, nada de migración in-place.** Un proyecto nace checklist o phased y no cambia.
- **Snapshot automático lunes (apertura) y viernes (cierre).**
- **Feed solo entradas explícitas**, no se auto-generan desde tareas completadas. Hay sí hito automático al cerrar fase, y bloqueo automático al pasar fase a estado `blocked`.

## 5. Automatismos ya implementados

En `phaseEditorModal.vue`, método `autoLog()`:
- Fase pasa a `done` → LogEntry tipo `milestone` con texto "Phase closed: <nombre>".
- Fase pasa a `blocked` → LogEntry tipo `block` con texto "Phase blocked: <nombre>".
- Fase pasa a `active` desde cualquier otro estado → LogEntry tipo `milestone` con texto "Phase started: <nombre>".

El snapshot semanal (`App.vue:maybeShowWeeklySnapshot`) corre al final de `finishInitialLoad()`. Si es lunes y `lastMondaySnapshot !== hoy`, dispara el prompt. Igual los viernes.

## 6. Pendientes conocidos

### Pequeños
- La vista Timeline no incluye un botón de "zoom" temporal. Si el proyecto es muy largo (más de 6 meses) las barras se amontonan.
- `PhaseEditor` no reordena fases con drag. El campo `order` existe y hay mutation `reorderPhases`, pero sin UI.
- El contador de tareas por fase (cuántas pendientes/cerradas) no se muestra en la barra. Se puede añadir en próxima ronda.
- Los proyectos phased pintan la lista de tareas igual que los checklist cuando toggle en `Tasks`. Las tareas no están filtradas por fase. Decisión futura: ¿añadir un sub-filtro por fase?

### No urgente
- Si cambias un `project.endDate` manual que ya tenía fases más allá, el Timeline va a cortar las barras. Mitigation: `phasedProjectHelper.projectRange()` ya añade margen de 7 días a la última fase si no hay endDate manual.
- Los IDs de phase y log entry se generan con `Date.now() + Math.random()`. Suficiente para un uso personal, no multi-device. Si en el futuro hay sync, pasar a UUID real.

### Para discutir
- ¿Mostrar snapshot history? Las entradas con `snapshotKind` ya se pueden filtrar fácilmente desde el feed, pero no hay vista dedicada.
- Export del log de un proyecto como markdown para informes. Sería 1h de curro aprovechando `exportTool.js`.
